### 最大的结构性缺口：新代码不可达

```

  campaign.py 275 · runner.py 250 · coding.py 199 · models.py 197
```

而是**把已有模块接成一条管线**。

## 三、每个任务的执行模板（TDD 硬纪律）

```
1. 读目标区域（不凭记忆构造 oldText）
2. 写 RED：失败测试先落，拿到具名失败输出（模块不存在 / 断言失败），归档为证
3. GREEN：最小实现使之通过
4. 本地：ruff check --fix + ruff format + mypy → 全洁净
5. 闸门：scripts/verify.py（T-045 未完成前，若红必须证明红只是 2 个已知间歇）
6. 账本：requirements.py set <ID> complete --evidence <真实文件与具名测试函数>；check 必须 0 问题
7. 提交：提交信息写清 RED 形态、修正过的错误假设、以及闸门真实状态
```

## 四、风险与对策

| 编号 | 风险 | 对策 |
|---|---|---|
| **R1** | **T-045 闸门间歇**（现红） | **先做区分实验**：在失败时判定任务究竟是"超时"还是"挂死"（等待是否会最终完成）。若为超时 → 把约 50 处魔法 deadline 收敛为一个**共享的负载容忍常量**；若为挂死 → 真因定位 `/quit` 竞态。**禁止猜测修补 `terminal.py`** |
| R2 | 新模块继续孤立 | A3 是**门禁**：A3 未完成前不新建评测模块，只接线 |
| R3 | Judge 过度建设 | verifier-first；能写成断言的一律不用 Judge；不默认多模型 |
| R4 | 真实模型费用 | 累计 ≤30 次求解，先估算后调用；E1 先出费用估算再执行 E2 |
| R5 | 结构债（`campaign` 275、`runner` 250、`runtime_bench` 493 行） | `runtime_bench`（P7-1）本轮不动；`campaign`/`runner` 在 A3 重写时顺带拆到 ≤200 行 |
| R6 | 台账与实际脱节 | 每任务后 `requirements.py check`；evidence 必须指向真实存在的文件与**真实覆盖该场景**的具名测试 |
