# P6 重构决定：按《深入理解 AI Agent》第 7 章简化

**决定人：用户。** 原 P6（8 个任务）被判为过重且重心错位。依据
[ai-agent-book 第 7 章《Agent 的评估》](https://github.com/bojieli/ai-agent-book/blob/main/book/chapter7.md)
重构为四块。统计要求：**做配对比较 + 置信区间**（用户明确选择）。

## 1. 第 7 章的骨架（采用）

- **环境五要素**：数据集 / 可重置的环境状态 / 原子工具接口 / Rubric + `reward_basis` /
  执行协议（终止信号、轮数上限、耐心耗尽早退）
- **任务四要素**：`ticket`、`user_scenario.instructions`（known/unknown/task）、
  `initial_state.initialization_actions`、`evaluation_criteria`
  （`actions` / `env_assertions` / `communicate_info` / `nl_assertions` / `reward_basis`）
- **指标**：`Pass@k = 1-(1-p)^k`（能力上限）、`Pass^k = p^k`（业务可靠性）、日常看 `Pass@1`
- **统计**：`SE ≈ sqrt(p(1-p)/n)`；同批任务做**配对分析**（McNemar / 配对 bootstrap）；
  每种配置 3–5 个随机种子；注意多重比较
- **自动化核心**：**LLM-as-a-Judge** + **失败归因定位首个错误**（不是整条轨迹打分）
- **回归形态**：端到端回归 vs **轨迹前缀回归**（冻结上下文，只要求下一步，答案为
  可接受动作集合 + 禁止动作列表）
- **Rubric**：`dimensions[]` 带 `name` / `weight`（essential/important/**veto**）/ `scoring`；
  幻觉等维度可设 veto 一票否决

## 2. 重构后的 P6（四块）

| 块 | 内容 | 任务 |
| --- | --- | --- |
| ① 环境 | 五要素 + 任务四要素 + 可重置 + 执行协议 + 原子工具 | T-028 (RED) / T-029 (GREEN) |
| ② 判分 | Rubric（weighted + veto）+ LLM-as-a-Judge + **首错归因** | T-030 (RED) / T-031 (GREEN) |
| ③ 统计 | `Pass@1/@k/^k` + **配对比较 + 置信区间** + 多种子 + 任务族分组 | T-032 (RED) / T-033 (GREEN) |
| ④ 真实跑 | 失败轨迹→新任务回流 + V01–V06 + `run bench` 真实小样本 + 成本账本 | T-038/39 (RED/GREEN) + T-040/41 |

## 3. 明确删除的复杂度（及其理由）

| 原计划 | 处置 | 理由 |
| --- | --- | --- |
| P6-5 OTel 兼容关联字段 + 资产版本事件 | **删除 OTel 兼容层**，降级为「一次运行可追溯」：task/run/trial/call 关联 + 首错归因 | 第 7 章只要求可追溯与首错定位，OTel 兼容是我自己加的基础设施 |
| P6-4 Runtime / Capability / Learning 三类套件 | **删除**，改为「指标口径（Pass@1/@k/^k）+ 任务族分组」 | 书里的分类维度是指标口径，不是三套不同架构 |
| P6-3 全维度 CampaignManifest | **降级**为：模型 + Harness 版本 + 任务集 hash + rubric + seed；够复现即可 | 原设计逐维铺字段属过度设计 |
| P6-6 人工校准记录模型 | **删除**，只保留「失败轨迹→新任务」 | 第 7 章的 trace→task 不需要独立的校准记录模型 |
| （原计划缺失） | **新增**：LLM-as-a-Judge、首错归因、配对统计、Rubric veto | 前三者是第 7 章的核心，而我原计划里几乎没有 |

## 4. 对账本的影响（必须显式记录，不得掩盖）

原 `requirements.json` 的 P6-1…P6-8 来自计划文档，措辞不变。重构后：

- **P6-1**（EnvironmentBackend / 多轮 / 独立 grader / 参考解准入）→ ① + ② 覆盖，语义不变
- **P6-2**（执行、取消、验收预算与失败成本账本）→ 执行协议（轮数/耐心/终止）+ 成本账本覆盖；
  「三层 deadline」降级为执行协议，**属简化，需在验收说明中标注**
- **P6-3**（Manifest 绑定全维度）→ **降级**，见上表；完成时必须在 evidence 里写明只绑了
  模型/Harness/任务集/rubric/seed
- **P6-4**（三类套件 + 任务族拆分）→ **改为指标口径 + 任务族分组**，属简化
- **P6-5**（OTel 兼容字段 / 重试投递阶段 / 资产版本事件）→ **部分不做**：保留可追溯与
  重试/投递阶段，**不引入 OTel 兼容层**；完成时写明这一偏离及用户裁定
- **P6-6**（候选案例→TaskSpec 回流 + 人工校准）→ 轨迹回流保留，人工校准记录模型删除
- **P6-7**（V01–V06）→ 不变
- **P6-8**（`run bench` 真实小样本 + SQLite 账本/轨迹 + S08）→ 不变

**结论：P6 的交付会比计划文档更简单，且必须把每一处简化写成有据可查的偏离，而不是把
P6-x 标成完成却按原措辞宣称。** 这份文件就是那些偏离的记录。

## 5. 为什么这不是"降低标准"

删掉的是**架构层数**（OTel 兼容、三类套件、全维度清单、校准模型），增加的是
**测量严谨度**（Judge 判分、首错归因、配对比较、置信区间、veto 维度）。

简历第 3 条要求"报告样本量、区间与成本"——区间以前根本做不出来，现在有了；
简历第 5 条要求"独立环境验收、重复试验与消融对比"——判分与统计现在是按第 7 章的
方法做的，而不是我自己发明的。
