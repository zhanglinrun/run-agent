# 检查点 05：模型输入证据与固定 Skill 包

日期：2026-09-10。完整改造仍在执行，本检查点不是整体完成声明。

- Core 增加与存储后端无关的 before_model_request 钩子。在扩展 context transform 与工具历史修复后、Provider 调用前记录实际 system/messages/tools/model。Coding 的命名、压缩与分支摘要请求也记录输入。
- 每次输入按内容分块保存于 SQLite；相同消息、工具和资源输入共享不可变块。读取验证清单和块哈希，缺失或篡改明确失败。
- 完成事务绑定同一 run/session/branch 的任务输入快照；命名等辅助请求不会覆盖最终任务快照引用。取消发生在输入写入完成、Provider 尚未调用之间时，保留输入证据和 cancelled 状态，不将它当作模型调用证据。
- 扩展通过 services.snapshots.read(id) 只读访问本会话的固定输入；受管理任务拒绝缺失或跨会话的快照引用。每次读取返回独立数据，不允许通过修改返回值修改历史。
- Skill 固定整个目录：正文、脚本和引用文件按哈希存为产物，恢复为独立版本目录。模型索引和 /skill 命令指向该目录；当前会话不跟随原文件修改，reload 才重新捕获。每次模型调用前验证缓存，损坏时阻止调用。
- Skill 包当前限制为 1024 个文件、16 MiB；目录链接、文件链接和非普通文件拒绝打包，.git 与 __pycache__ 不进入包。只读文件权限防止误改，不声称是 shell 或 Python 扩展的安全沙箱。包内容通过现有 SQLite 一致性备份和产物引用恢复。
- run.resources 事件保存资源内容、包版本及来源摘要。启动、恢复、reload、分支有明确事件；启动/reload 的事件与扩展绑定在同一事务提交，分支事件与分支创建一起提交。恢复与历史分支使用已保存的文件资源；当前信任边界变化时重新发现允许的资源。
- 修复初始化期间首条终端输入被丢弃的问题：启动完成前提交的输入排队，启动完成后执行；新增可控启动阻塞验证。
- /resume 继续沿用 Provider instrumentation 配置。

验证：88 项新版测试通过，1 项因当前 Windows 无创建符号链接权限而跳过；mypy 检查 148 个源文件通过，Ruff 与 diff whitespace 检查通过。wheel/sdist 构建成功，全新安装环境在源码目录外验证唯一 run 入口、空库初始化、会话持久化、模型输入快照、Skill 包、reload 与恢复。没有调用真实模型。

证据：snapshot-tests.xml、distribution-check-05.json。安装环境：.run/redesign/install-env-05。当前 schema 为 5，仅初始化当前版本，不增加迁移或兼容分支。

仍需完成：扩展 resource provider 与一致版本读取、全部扩展贡献/显式启动覆盖的恢复规则、基于上下文快照加速恢复及其与全事件重建的对照。现有模型输入快照用于核对实际请求，不能直接当作会话状态缓存。任务输入不是最终产物；experience 还需按完成回执读取输出证据。Gateway、experience、独立评测与真实模型实验尚未完成。
